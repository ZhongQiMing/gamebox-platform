# 全玩法限红清单

> 这份表列的是**实际生效**的限额。凡是「后台能配但代码不读」的，单独标在末尾的缺口一节，
> 不要照着那些数字做运营判断。
>
> 修改限红前先看最后一节「改限红要注意什么」。

---

## 一、所有游戏的通用底线

| 项目 | 值 | 能不能改 |
|---|---|---|
| 单注最低 | 1 | 后台「游戏管理」逐游戏可改 |
| 单注最高 | 100,000 | 后台「游戏管理」逐游戏可改 |
| 单笔派彩封顶 | 下注额 × 5000，且绝不超过 **2,000,000 万**（2000 万） | 代码常量，改要发版 |
| 玩家账户 | 不允许透支 | 代码写死 |

派彩封顶的完整规则：`min(下注额 × max(5000, 该玩法挂牌赔率), 2000万)`。
挂牌赔率超过 5000 倍的玩法（只有六合彩四全中 9000 倍）按挂牌赔率抬相对上限，
但 **2000 万这个绝对天花板任何情况都不会破**。

## 二、彩票 / 聊天室类（7 款）

ssc（时时彩）、ffc（分分彩）、kuai3（快三）、speed-racing（极速赛车）、
bjsc（北京赛车）、speed-boat（幸运飞艇）、lhc（六合彩）

| 项目 | 值 |
|---|---|
| 单注 | 1 ~ 100,000 |
| 一次批量最多 | 50 注 |
| **高赔率玩法单注上限** | 挂牌赔率 **超过 500 倍**的玩法，单注最多 **50** |
| 单期累计上限 | **没有** |

高赔率这条只命中六合彩两个玩法：

| 玩法 | 赔率 | 单注上限 |
|---|---:|---:|
| 四全中 | 9000 倍 | 50 |
| 三全中 | 670 倍 | 50 |

其余 6 款彩票最高倍率都在 260 倍以内，不触发这条。

**要注意的**：彩票**没有**单期累计限红。一个玩家理论上可以在一期里下满 50 注 ×
100,000 = 500 万。单期防爆完全靠开奖时的软控挑号，不是下注口拦。

## 三、牌桌类（4 款）

zhajinhua（炸金花）、douniu（斗牛）、baccarat（百家乐）、dragon-tiger（龙虎）

### 单注上限（按方向）

| 游戏 | 方向 | 单注上限 | 为什么这么低 |
|---|---|---:|---|
| 炸金花 | 顺金、豹子 | **500** | 赔率 100 倍 |
| 斗牛 | 小牛、花牛 | **200** | 赔率 100 / 90 倍 |
| 斗牛 | 牛牛 | **2,000** | 含本总赔率 6.84 |
| 龙虎 | 和 | **5,000** | 赔率 8 倍 |
| 百家乐 | 全部 | 100,000 | 无专属限制 |
| 其余方向 | | 100,000 | |

### 单局累计上限（四款共用）

| 项目 | 值 | 怎么执行 |
|---|---:|---|
| 单个玩家 · 单局 · 同一方向累计 | **200,000** | 数据库聚合 + 按玩家的锁 |
| 全桌 · 单局 · 同一方向累计 | **2,000,000** | Redis 原子操作，判上限与累加不可分割 |

同一局不能对冲下注：庄和闲互斥、龙和虎互斥。

## 六、下注频率限制

| 项目 | 值 | 能不能改 |
|---|---|---|
| 下注接口 | 每玩家 **10 秒内最多 100 次** | 环境变量 `BET_RATE_LIMIT` / `BET_RATE_WINDOW_SEC` |
| 其他接口 | 每 IP **每分钟 120 次** | 环境变量 `THROTTLE_LIMIT` / `THROTTLE_TTL_MS` |

下注是按**玩家**算的，所以同一个网吧/同一个 WiFi 下多人一起玩不会互相挤掉。
其他接口仍按 IP 算。

## 七、已知缺口（上线前请知情）

### 1. 平台单边限红是「赔率盲」的

`2,000,000` 这个数管的是**押了多少**，不是**可能赔多少**。同样押满 200 万，
不同方向的最坏赔付差几十倍：

| 游戏 | 最危险的方向 | 押满 200 万时的原始赔付 | 逐注封顶后 |
|---|---|---:|---:|
| 炸金花 | 顺金 / 豹子（100 倍） | 2.02 亿 | 每注压到 2000 万以内 |
| 斗牛 | 小牛（100 倍） | 2.02 亿 | 同上 |
| 百家乐 | 对子（11 倍） | 2400 万 | 同上 |
| 龙虎 | 和（8 倍） | 1800 万 | 1800 万 |

注意「逐注封顶」是**按每一注**算的，不是按整桌合计。所以一桌上很多小注一起中，
合计赔付仍可能远超 2000 万。

更稳的做法是把限红改成按「潜在赔付」而不是「押注额」来卡。这一项你之前说先放着，
所以没有动。

### 2. 彩票和街机都没有单局累计限红

见上文各节。彩票靠软控在开奖时兜，街机是一人一局。

### 3. 房间级限红定义了但不生效

数据库里有 `RoomGameConfig.minBet / maxBet` 两个字段，但代码**从来不读**。
实际生效的只有平台「游戏管理」里那一套。不要以为改房间就能给某个房单独设限红。

### 4. 客户端比服务端宽松的地方

客户端不做完整预检，会让玩家点到服务端才被拒。功能上安全（服务端一定拦），
但体验上是「点了才知道不行」：

| 场景 | 客户端允许 | 服务端实际 |
|---|---|---|
| 彩票手动输入 / 全押 | 到余额为止 | 100,000 |
| 六合彩四全中 | 可选 50,000 筹码 | 50 |
| 牌桌连点累计 | 无预检 | 200,000 / 2,000,000 |

## 八、改限红要注意什么

1. **单注上限改大之前先看赔率。** 高赔率方向的单注上限是按赔率倒推的
   （赔 100 倍的只给 500），不是随便定的。把它调大等于直接放大最坏赔付。

2. **牌桌单边 200 万这个数不要轻易调大。** 它是全桌合计，赔率盲，
   调大之后最坏赔付是按倍率放大的。

3. **高赔率那条 50 的上限不要动。** 六合彩四全中是 9000 倍，
   押 100 就要赔 90 万；上限放到 1000 就是 900 万一注。

4. **改完一定要两头都改。** 服务端是唯一权威，但客户端的筹码档位和方向上限
   也有一份（`games-assets/_table-common/table-shell.js` 与各桌的 `sideLimits`），
   只改服务端会让玩家一直点到被拒。
