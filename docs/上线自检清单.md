# 上线自检清单（贴合本项目）

> 这份是「整个系统能不能上」的自检。逐游戏的玩法核对在
> [`上线验收清单.md`](./上线验收清单.md)，两份配合用，不重复。
>
> 来源：外部给的通用手游检查清单，按本项目实际形态重写——
> 删掉用不上的（iOS、广告 SDK、多语言、离线玩法），
> 补上它没覆盖但本项目真正会出事的（两本账、飞盘、软控、按房隔离）。
> 第四节列了删掉的项与原因，需要对外交代时直接引用。

## 一、一条命令能验的

跑完全绿再往下走。任何一条红的都不要上。

| 命令 | 验什么 | 红了意味着 |
|---|---|---|
| `pnpm -r lint` | 三端静态检查 | 有语法/类型隐患，或又混进死代码 |
| `pnpm check:encoding` | H5 中文编码、内联脚本、ps1 的 BOM、sh 的换行 | 游戏页面乱码，或脚本传上服务器跑不起来 |
| `pnpm audit:rtp` | 全部玩法的理论 RTP | 出现「平台负期望」= 玩家可稳定套利 |
| `pnpm security:gate` | 官方 npm 审计、Semgrep、Gitleaks、Trivy 与 CycloneDX SBOM | High/Critical 依赖、代码缺陷、密钥或镜像配置风险 |
| `pnpm --filter @gamebox/server test` | 服务端单测 | 金额取整、赔率口径、分账公式、客服可达面 |
| `pnpm --filter @gamebox/server test:db` | 资金层集成测试（真库） | 幂等、并发扣款、下分冻结、盘分额度、注销 |
| `pnpm --filter @gamebox/client-app test` | 玩家端单测 | 订单号格式、APK 接口地址、余额分房、缓存兜底 |
| `pnpm build:server` / `build:app` / `build:admin` | 三端构建 | 类型错误，或打包配置坏了 |
| `bash scripts/verify-runtime-security.sh`（服务器） | 最终镜像 Trivy、非 root、只读根目录、capabilities、网络隔离 | 构建阶段安全配置没有真正落到运行容器 |

要点：

- `audit:rtp` 末尾还有一段**软控仿真**，看「全候选非法」和大奖频率。
  改过赔率表、权重表、软控参数后必须重看这一段。
- `test:db` 会自动建 `<库名>_test` 并迁移，**不碰开发库**；
  库名不以 `_test` 结尾会直接拒跑。
- 改 `PointsService`、`writeAgentQuotaInTx`、账户下限、任何幂等键规则后，
  `test:db` 是必跑项，不是可选项。
- `security:gate` 只接受官方 `https://registry.npmjs.org` 审计结果；CI 镜像须预装固定的
  Semgrep 1.172.0、Gitleaks 8.30.1、Trivy 0.73.0。版本不符、扫描器缺失、超时或 registry 不可用都会直接失败，
  不得把“没扫到”当成“没有漏洞”。SBOM 输出到 `scripts/security-artifacts/sbom.cdx.json`，
  发布流水线应把它与镜像一起归档。
- `verify-runtime-security.sh` 在服务器读取当前 `GAMEBOX_VERSION`，对最终的 server/web
  镜像跑 Trivy，并实际尝试写根目录、写上传卷、从 web 连接 Postgres。Trivy 缺失也会失败，
  不能只看 Dockerfile 就判定“已降权”。

## 一点五、上线当天必须人工确认的（代码验不了）

这几条没有任何自动检查能兜住，漏一条就是事故。

| # | 确认什么 | 怎么确认 | 漏了会怎样 |
|---|---------|---------|-----------|
| 0 | **首次部署后跑过一次初始化** | 见下方「首次部署必做：初始化数据库」 | 迁移只建空表：没有游戏目录、没有赔率、没有管理员。后台登不进去，进去也一个游戏都没有，而且 postgres 在 internal 网络上没法从外面补数据 |
| 1 | 生产 `JWT_SECRET` 是部署脚本生成的随机串 | `grep JWT_SECRET /opt/gamebox-platform/.env.prod`，应为 64 位 hex | 沿用开发密钥＝任何人可伪造管理员 token（启动门禁现在会拒，但别指望它） |
| 2 | 管理员口令已改，不是 `Admin@123456` | 用旧口令登录应失败 | 文档里写着的口令＝全站后台公开 |
| 3 | 备份定时任务真的在跑 | `crontab -l` 有 backup-on-server.sh；次日看 `/opt/gamebox-backups/` 有新包 | 需要恢复那天才发现一份都没有 |
| 4 | 异地副本已配 | `backup.env` 里有 `BACKUP_OFFSITE_CMD`，或明确安排了每周手工下载 | 硬盘坏／服务器回收＝库和备份一起没 |
| 5 | 探活告警能收到 | 停掉 server 容器，5 分钟内应收到 Telegram | 半夜挂了没人知道 |
| 6 | 探活地址是 **8080** 不是 3000 | `grep HEALTH_URL /opt/gamebox-platform/health-alert.env` | compose 只映射了 `127.0.0.1:8080`，server 不对宿主机开端口。填 3000 会每 5 分钟误报一次「服务已挂」，最后告警被当噪音关掉 |
| 7 | 宿主机 443 + 证书 + HSTS 已开 | 浏览器访问域名是 https 且无警告 | 登录态与上下分走明文 |
| 8 | 证书自动续期真的能跑通 | 手动跑一次续期命令（dry-run），别等 90 天后 | 到期整站 https 报警告 |
| 9 | `TRUST_PROXY=2` | `grep TRUST_PROXY /opt/gamebox-platform/server/.env.production` | 按 IP 的限流与同 IP 风控全部失灵 |
| 10 | 退役游戏不在大厅 | 玩家端大厅无「麻将」类条目 | 进去下注会打到没有引擎的游戏上 |
| 11 | 真机进一次游戏 | 手机开牌桌与彩票各一个，退回大厅再进 | iframe 内的素材路径与暂停逻辑本地构建看不出问题，只有真机能验 |
| 12 | API 限流在宿主机按真实 IP 生效 | `nginx -T` 有 `gamebox_api_ip`；出口 A 打满后出口 B 仍 200 | 容器层按 Docker 网关计数会变成全站共享桶，攻击者可让所有人 429 |

第 3、5 条现在由 `deploy-on-server.sh` 自动写入 crontab，但**仍要亲眼确认一次**：
自动写入失败只会打印一行提示，不会让部署失败。

### 首次部署必做：初始化数据库

`prisma migrate deploy` 只建表。平台要能跑起来还需要一批基础数据，它们全在
`server/prisma/seed.ts` 里，而**生产部署从不自动执行它**：

- 11 个游戏的目录 + 各自 active 的 GameConfig（爆率/赔率）
- 代理等级 V1–V5
- 平台积分账户与那 1 亿的开账分录
- 唯一的管理员账号

不跑就是个空平台：后台没有账号可登录，进去也没有游戏；而 postgres 只挂在 compose
的 `internal` 网络上、一个对外端口都没开，所以**没法从外面连进去补数据**。

`deploy-on-server.sh` 现在会在迁移后自查游戏数与管理员数，缺了就打印告警和现成命令。
手动执行（口令换成你自己的强口令）：

```bash
cd /opt/gamebox-platform
SEED_ADMIN_PASSWORD='你的强口令' docker compose \
  --project-directory /opt/gamebox-platform \
  -f /opt/gamebox-platform/docker-compose.prod.images.yml \
  --env-file /opt/gamebox-platform/.env.prod \
  run --rm --no-deps -e SEED_ADMIN_PASSWORD server node dist-seed/prisma/seed.js
```

要点：

- **幂等**，重复跑安全：已有管理员会跳过，其余都是 upsert。不确定跑过没有就再跑一次。
- 生产环境下不设 `SEED_ADMIN_PASSWORD`、或沿用开发弱口令 `Admin@123456`，脚本会**直接报错拒绝建号**。
- 演示房间默认不建（要 `SEED_DEMO_ROOMS=1` 才建），生产别加这个变量。
- 用户名固定 `admin`。**忘记口令只能改库**，系统没有「重置管理员密码」接口。
- 走的是 `dist-seed/`（随镜像编译好的产物）。生产镜像按 `--prod` 装依赖、且不带 `src`，
  所以 `pnpm prisma:seed`（`ts-node prisma/seed.ts`）在服务器上是跑不了的，别照开发文档抄。
- **别自己加 `-e DATABASE_URL`**：`server` 服务已通过 `env_file` 加载
  `server/.env.production`，里面就是对的连接串；显式传会覆盖它，而你的 shell 里
  没有 `DB_PASSWORD`，展开成空密码只会得到认证失败。

### 已经由代码兜住的（了解即可，不用逐条验）

| 项 | 现状 |
|---|---|
| 密码强度 | 玩家 8 位起、运营账号 10 位起，都必须字母+数字混合 |
| 密码哈希 | bcrypt cost 统一 12 |
| 登录限流 | 10 次/分/IP，叠加 Redis 15 分钟账号+来源/IP 临时退避；错密不永久冻号 |
| 二次验密 | 软控参数、软控偏置、控奖策略、删房、对账补记 |
| CSP | API 侧 `default-src 'none'`；页面侧在容器 Nginx 配置里 |
| JWT 有效期 | 生产 8 小时（部署脚本写入），改密/冻结即刻失效 |
| 上传 | 头像与客服收款码都验文件头，不认 MIME 声明 |
| 聊天表 | 每日 04:20 清理 15 天前记录，分批删不锁表 |
| 退役游戏 | 大厅、详情、SLOT 引擎三处硬过滤，改回 ONLINE 也进不去 |
| 玩家资金接口 | 上分／下分／返水领取／活动领取都加了 `@Roles('PLAYER')`，运营账号调不到 |
| 密码字段 | 重置密码与二次验密走 DTO 并限长 128，挡住超长串拖垮 bcrypt |
| 边缘限流 | 宿主机 TLS Nginx 对 `/api/` 按真实来源 IP 限 30r/s（burst 60）；容器 Nginx 不限流，避免 Docker 网关变成全站共享桶 |
| 对账探活 | `/api/health/reconcile` 需要 `X-Recon-Token`，密钥由部署脚本生成并同步给探活脚本 |
| Node 堆上限 | `NODE_OPTIONS=--max-old-space-size=768`，比容器 1g 限制低一档，OOM 时先抛 JS 错误而不是被内核静默 kill |

## 二、钱：本项目最容易出事的地方

通用清单只说「积分不能负、要有流水」，这套系统比那复杂——**有两本账**。

### 2.1 两本账必须同时对得上

| 账 | 不变量 | 破了说明 |
|---|---|---|
| 积分账 | 逐账户 `SUM(PointsLedger.amount)` == `balance` | 有代码绕开 `PointsService` 直接改余额 |
| 盘分账 | 逐代理 `SUM(AgentQuotaLedger.delta)` == `pointsQuota` | 有代码绕开 `writeAgentQuotaInTx` |
| 冻结额 | 玩家 `frozen` == 待审下分单合计 | 下分审核流程中断，钱卡在冻结里 |
| 负数哨兵 | 玩家 `balance`/`frozen` 不为负 | 扣款下限保护被击穿 |

- [ ] 后台「资金对账」点「立即对账」，四项全过
- [ ] `GET /api/health/reconcile` 带密钥头可访问（对得上 200，有差额 503）

      ```bash
      curl -H "X-Recon-Token: $(grep '^RECON_HEALTH_TOKEN=' /opt/gamebox-platform/.env.prod | cut -d= -f2)" \
        http://127.0.0.1:8080/api/health/reconcile
      ```

      这个接口会回差额金额与对不上的科目，属于账务健康度，不再公开。
      不带头应返回 403；生产没配 `RECON_HEALTH_TOKEN` 时接口整个关闭（宁可探活报错也不裸奔）。
- [ ] 自动对账定时任务在跑（每天 05:00 上海时间）

**查出差额先查原因再修**。差额一定产生于最近 24 小时，拉该账户这段时间的
流水与操作日志比对。定位后先改代码堵源头，再补记一条 `ADJUST` 说明差额来路，
**不要直接改余额**。

### 2.2 按房隔离

玩家持分是**按房间分开的**，跨房余额互不可用。

- [ ] 同一玩家在 A 房、B 房余额独立，切房不串
- [ ] 未进房时余额显示 0，不残留上一个房的数字
- [ ] 上下分、下注、派彩都落在正确的房账本

### 2.3 限红与封顶

- [ ] 单笔上分最低 200、下分最低 500、单笔上限 200000（后台可改，改完复核）
- [ ] 单局派彩封顶：本金 × 5000 与 2000 万取小
- [ ] 挂牌赔率高于 5000 倍的玩法（六合彩四全中 9000）按赔率放行，页面写多少就赔多少
- [ ] 触顶时服务端有 `派彩触顶` 错误日志，且有人看

### 2.4 幂等与并发

- [ ] 上下分、下注重复提交只生效一次（`test:db` 已覆盖，人工再点两次确认）
- [ ] 连点下分不会冻结出多笔（**已知弱点**：`applyWithdraw` 是事务外读余额再冻结，
      冻结本身有原子守卫不会透支，但可能生成多张待审单，需客服驳回）

## 三、其余必须人工过的

### 3.1 账号与登录

- [ ] 停用玩家后，手机上已登录的那台**下一次请求就掉线**（`tokenVersion` 生效）
- [ ] 改密后旧登录态立即失效
- [ ] 登录失败多次会锁定，重置密码后解锁
- [ ] 注销后无法登录，账号名不能再注册，后台显示「已注销」而非「停用」
- [ ] 注销前有余额时，二次确认弹窗报出具体金额；确认后余额转回平台池并留流水

### 3.2 权限边界

- [ ] `console.controller.cs-scope.spec.ts` 通过（客服只该有 8 个接口）
- [ ] 控制台类级默认角色里**没有 CS**——否则以后每加一个接口客服都自动能读，且不会报错
- [ ] 代理只能看到自己房间的玩家；子账号只读

### 3.3 对外暴露面

- [ ] `TABLE_WS_ENABLED` **不要设**：牌桌 Socket.IO 网关默认不注册，
      `/socket.io/` 应返回 404。它推整桌快照（含他人下注），没有客户端在用
- [ ] Postgres / Redis 端口不对公网开放。compose 里这两个服务本来就没有
      `ports:` 映射，**别为了"方便连库看一眼"临时加上去**
- [ ] 防火墙只放行 22 / 80 / 443
- [ ] SSH 已改成密钥登录、禁用密码（`PasswordAuthentication no`）
- [ ] `.env.prod` 不在 git 里；密钥不是示例默认值

`CORS_ORIGIN` 与 `HOST` 这两项容易照抄通用建议写错，说明一下：

| 项 | 实际情况 |
|---|---|
| `CORS_ORIGIN` | **同域部署不用配**。网页端与后台跟接口同一个 Nginx server 块，压根不走 CORS；App 的 WebView 来源已在代码里无条件放行。只有后台单独用别的域名时才需要追加 |
| `HOST` | **不用设 `127.0.0.1`**。`server` 容器在 compose 里没有任何 `ports:` 映射，只挂在 docker 内网，监听 `0.0.0.0` 不等于暴露公网。真正对外的只有 web 容器的 `127.0.0.1:8080` |

### 3.4 玩法与展示一致

- [ ] 面板赔率 = 服务端 `pay-table`，不是前端写死的兜底值
- [ ] 玩法说明里的注数与实际扣款一致
      （组三选 2 码 = 拆成 112/122 两注、扣两注钱）
- [ ] 三军「出现多次只派彩一次」，页面与结算一致
- [ ] 机器人氛围注不改任何人的余额，也不进账本

### 3.5 客户端打包

- [ ] APK 构建前 `client-app/.env.app` 的 `VITE_API_ORIGIN`、`VITE_ASSET_ORIGIN`
      已改成真实域名（还是占位符时构建会直接失败，这是故意的）
- [ ] 装机后能登录、能下注、素材能下下来（占位符没改的包是「能装能开但用不了」）
- [ ] 隐私政策页在**登录前**可打开（应用商店审核要点）

### 3.6 发布与回退

- [ ] 镜像带版本号，服务器上留有可回退的旧版；看到 `latest` 说明流程不对
- [ ] 迁移写成天然可回滚：加字段先加可空的发一版，下一版再补非空约束
- [ ] **别在服务器上跑 `docker system prune -a`**，会清空全部可回滚版本
- [ ] 备份含数据库 + `.env.prod` + 上传文件，三样缺一不可
- [ ] 上线前做过一次恢复演练（`restore-on-server.sh --rehearse latest`）

## 四、原清单里不适用的项，以及原因

需要对外解释时直接用这一节。

| 原清单项 | 为什么不适用 |
|---|---|
| iOS / Xcode 版本、On-Demand Resources | 只发安卓 APK 与网页版，没有 iOS 端 |
| 第三方 SDK（广告 / 统计 / 分享） | 一个都没接，也不打算接 |
| 游客登录、第三方登录、手机号登录 | 只有账号密码注册登录，不收手机号、不实名 |
| 支付回调、补单机制 | 没有在线支付，上下分是代理线下收款、后台人工审核 |
| 多语言 / 多区域 / 货币单位 / 时区 | 单语言单区域，时间统一按上海时区 |
| 增量热更新 | 网页版刷新即最新；APK 走整包更新 |
| 离线玩法 | 所有玩法都必须连服务端结算，断网不该能玩 |
| 无障碍读屏 | 未做，也不在本期范围 |
| 截图 / 录屏遮挡 | 未做 |
| 推送权限 | 没有推送通道 |
| 客户端与云端每 5 分钟比对 | 客户端不存核心数据，余额每次都从服务端拉，不存在两份数据 |
| 反外挂 / 内存注入检测 | 客户端不参与任何金额计算，改内存改不到账；风控在服务端 |
| 请求 SHA-256 签名 | 走 HTTPS + JWT；签名方案未做 |
| 单测覆盖率 ≥90%、圈复杂度 ≤10 | 没有强制门槛。当前测试集中在资金层与玩法判定，
  即「错了会赔钱」的部分，不追求整体覆盖率数字 |
| 内存 Crash 率、首帧 3 秒、帧率 ≥30 | 没有埋点也没有压测数据，无法给出数字。
  只做人工观感确认 |
| 数据埋点上报 ≥99.9% | 没有埋点系统 |

## 五、已知没做的，上线前自己决定

- **防沉迷未做**：不收实名、无时长限制。隐私政策里只写了「不面向未满 18 周岁」。
- **`applyWithdraw` 连点可生成多张待审下分单**（不会透支，但要人工驳回）。
- **开发库数据量偏大**（`RoomChatMessage` 百万级），会让备份持续膨胀，需定期清理。
- **`slots-mahjong` 已退休**，其库内 `payTable` 是对象而引擎要数组，
  一旦重新启用会在 `.map` 处直接报错。
