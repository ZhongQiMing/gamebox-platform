# 结算口径与显示名称

面向对账人：打开任何一页，先分清「这是看的」还是「这是结的」。

---

## 一、只有两本账

| | 经营账（看的） | 结账账（结的） |
|---|---|---|
| 用途 | 看今天/本期打了多少、走势 | 这期该收付多少，签字付钱 |
| 归期依据 | **下注时间** | **开奖时间** |
| 未开奖注 | **计入** | 不计（等开完落到它开奖的那一期） |
| 关盘注 | 计入（管理侧不计） | **不计** |
| 出现在 | 工作台、房间中心、房间详情、报表「经营」块、实时开奖 | 结算中心、房间详情→结算、报表「本期结账口径」块 |

**两本账永远不相等，这是设计。** 付钱只认结账账。

---

## 二、三级账本各管各的

**一条原则贯穿全链路**：每一级只看「我接到的单」，再拆成「我飞给上家的」和「我自己坐庄的」。
上家怎么处理我飞上去的单，不进我的账；下家自己关盘的单，也不进我的账。

底数只有三个桶，谁都从这三个桶取（`server/src/modules/console/flow-scope.helper.ts`）：

- `flown` 飞上台（平台坐庄）
- `agentFly` 代理飞出去的（上台 + 飞到总代）
- `all` 全部（再加代理自己坐庄）

| 角色 | 接到的（主数） | 我飞给上家 | 我自己坐庄 |
|---|---|---|---|
| 代理 | `all` | `agentFly` | `all − agentFly` |
| 总代 | `agentFly` | `flown` | `agentFly − flown` |
| 管理 / 总监 | `flown` | `flown`（＝飞上来的那批） | 不显示（恒 0） |

**核心恒等式——每一级飞出去的，正好是上一级接到的：**

```
代理接到 all ──飞出 agentFly──▶ 总代接到 agentFly ──飞出 flown──▶ 平台接到 flown
```

由此自然得到：

- 每一级：飞出去 + 自己坐庄 = 接到的
- 代理的「飞」= 总代的「合计」= 房间结算单收代理的数
- 总代的「飞」= 管理的「合计」= 总代表收总代的数

所以房间单和总代表**不是对不上，而是差着中间那一级**：
`房间单 = 总代表 + 总代自己坐庄那截`。

> 管理是例外：顶层没有上家，「飞」栏标的是「飞盘流水」＝飞上来的那批，
> 语义与下面两级相反；下级关盘不进平台账，也不占管理端栏位。

**关盘用橙色显示**（`--ops-closed-flow`）：关盘＝下级自己坐庄，平台不参与分成、赚不到钱，
配色要和飞盘（蓝）一眼分开，方便盯关盘占比。

### 每一级坐庄的钱都有独立校验

账本对不对，不能只看「流水加起来等于余额」（那只证明记账自洽，证明不了金额本身对）。
所以每一级坐庄的钱都拿**注单**这个独立来源反查：

| 层级 | 对账项 | 校验式 |
|---|---|---|
| 房间代理 | `credit_conservation` | 剩余信用+玩家持分+客服额度 = 合同额度 − 上家赢走的 + 整包 |
| 总代 | `general_house_ledger` | 盘分账 BET+WIN 净额 = 他坐庄那些注单的（下注额 − 派彩） |

两条都在 `fund-recon.service.ts`，每天 05:00 自动跑，也可在对账页手动触发。

## 四、结账流程

**切期是自动的，结钱是人工的——两件事分开。**

- 账期边界由 `shanghaiSettleBounds` 按周期自动算：周结＝上海周一 00:00，月结＝1 号，半月结＝15/30。
- 结账按**开奖时间**归期：输赢在开奖那一刻才定，**派完彩这一期才算完**。
  23:58 下注、00:03 开奖的那笔，落到它开奖的那一期，不会两头落空。
  未开奖的注 `settledAt` 为空，落不进任何账期，等开完自动进那一期——所以**不需要拦着不让结账**。
- 经营看板另一套：按**下注时间**归期且含未开奖，回答的是「今天打了多少」。
- 系统里唯一的定时任务是信用盘每小时 `:07` 的**封账快照**（`cronCloseDuePeriods`），它只记额度、玩家持分、超出，**不算流水、不算钱**。
- 真正算钱的结清（`persistSettle`）是人工点的。
- **信用盘额度加回按封账快照算**（加回额 = −`excessAtClose`），不按点结账那一刻的实时余额；
  加回额再叠加到**实时**额度上，封账之后的输赢与发分原样留给下一期。
- 占成、庄家盈亏这些按注单流水算，本来就按账期切，不受此影响。

流程：

1. 账期到点，自动切期。
2. 打开结算中心或房间详情→结算，随时可结，不受在飞注单影响。
3. 点结清 → 只收开奖时间落在本期的注单。
4. 落库冻成快照：房间单写 `RoomWeekSettle`，总表写 `GeneralPeriodSettle.roomsSnapshot`。
5. 已结账期再打开，直接回放快照，不重算（改档、补注单都不影响）。

**为什么不用拦未开奖的注：** 因为归期看的是开奖时间。

23:58 下注、00:03 开奖 → 按开奖时间它属于下一期，上一期结账时本来就不该算它，账单里没有它是对的。
等它 00:03 开完，`settledAt` 落在下一期窗内，下一期自然收得到。两期不重不漏。

早先按下注时间归期时才需要拦：那时这笔注属于上一期，但结账只取已开奖的，它进不去；
开奖后上一期已冻、下一期又按下注时间不要它，**两期都算不到，钱凭空消失**。
换成开奖时间后这个洞不存在了，拦截已撤掉，随时可以结账，提前结账也不受在飞注单影响。

**卡死的注单**（游戏该开没开）：不再挡结账，由资金对账的「吞单」检查报出来，单独处理。

### 为什么信用盘额度必须用封账快照

按流程「12 点自动封账、第二天对账」，结账那一刻新一期已经在下注。此时的实时余额里混着两样不属于上一期的东西：

1. 新一期玩家的输赢；
2. 已扣本金、还没派彩的在飞注单（下注即扣分，派彩要等开奖）。

拿它算额度加回，等于把下一期的钱结进上一期。所以加回额取封账快照的 `−excessAtClose`，再叠加到实时额度上——上一期结得干净，封账后的变动照样留在代理手里。

**账期刚结束、快照还没生成时（cron 每小时 :07 跑），结账会被拒绝**，提示等封账。超过 25 小时仍无快照（早于该机制的老账期）才按实时值兜底。

提前结账没有快照，那一刻的「现在」就是账期终点，本来就该用实时值。

## 五、注单归属

报表与结账都**只认注单自带的 `fly.roomId`**，口径完全一致。

**正常下注必定带房号。** 所有下注入口（彩票、牌桌、电子、街机、水果机）都先过 `requireOpsRoomId` + `requireRoom: true`：房号不是 6 位、房间不是 OPEN、或玩家不在该房未通过审核，直接拒绝下注。所以「未标记」正常恒为 0。

留这个分类是当报警器用：改前报表在缺房号时会**回退**到「该玩家最近通过审核的房」，这个回退才是问题——它让老注单在报表里有、在账单里没有，且玩家换房会改动历史报表。回退已删除，现在缺房号的注不摊进任何一间房，报表顶部直接红色告警。

看到这条告警只有两种可能：历史遗留单，或写入逻辑出了 bug。

上线前自查库里有没有老单：

```sql
SELECT count(*) FILTER (WHERE NULLIF(payload->'fly'->>'roomId','') IS NULL) AS 无房号,
       count(*) AS 总数
FROM "Bet";
```

## 六、重新下注自测清单

同一间房，用三种盘口各下一笔，等开奖后核对。

**准备**：现金房 111112（总代 zongdai1）、信用房 111113。

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 玩家飞盘开、总代飞盘开 → 下注 A | 三方都能看到：管理飞盘流水 +A；总代飞上台 +A；代理飞盘 +A |
| 2 | 总代整房飞盘关 → 下注 B | 管理**看不到** B；总代关盘 +B；代理飞盘 +B（飞到总代也算飞出去） |
| 3 | 代理整房飞盘关 → 下注 C | 管理看不到；总代关盘 +C；代理关盘 +C |
| 4 | 开奖前看房间列表 | 今日流水含未开奖，下标「未开奖 X」 |
| 5 | 开奖前点结清 | 能点；账单里不含还没开的那几笔（它们归下一期） |
| 6 | 全部开奖后核对恒等式 | 飞+关=合计；管理数=总代飞上台；代理飞盘−总代飞上台=B |
| 7 | 开奖后结清房间单 | 结账投注额 = A + B（不含 C） |
| 8 | 结清总代总表 | 结账投注额 = A（不含 B、C） |
| 9 | 报表「本期结账口径」块 | 数字与第 7、8 步账单一致 |

## 七、已知边界（上线前知悉）

- **成数中途改档**：账单存了当期成数快照；报表按当前成数实时重算，历史区间可能与账单不同。以账单为准。
- **BRANCH 只授权部分房**：总表会拒绝代结（`hiddenCount > 0`），报表合计也只含授权房。
- **`validFlow` 与投注额**：结账投注额取下注金额；佣金/回水另按 `validFlow` 计。两者在有对冲/作废时不等，故不共用一个名字。
- **CANCELLED 注单**：报表与结账都不计。开奖前计入的未开奖流水，若最终作废会回落。
