# 软控链路梳理

> 这份文档回答四个问题：软控**什么时候**会介入、**怎么**介入、**外面能不能查出来**、
> **内部怎么查**。
>
> 全文只描述系统实际行为，不描述后台界面上写着但不生效的东西
> （那些在「界面 vs 实际」一节单独列出）。

---

## 一、一句话总览

软控**不改赔率、不改注单、不动钱**。它只做一件事：在开奖前多摇几把种子，
从若干个候选结果里挑一个，然后照常结算。

所以它改变的是「开出什么」，不是「怎么算钱」。这一点很重要——
账目正确性与软控无关，两者是分开的两套东西。

---

## 二、三条独立链路

三个品类各走各的，参数和触发条件都不一样。

| 品类 | 挑什么 | 候选怎么来 | 目标 |
|---|---|---|---|
| 彩票（7 款） | 开奖号码 | 同一把种子的第 N 页 | 单期护栏 + 当日净额 + 偏置 |
| 牌桌（4 款） | 牌面 | 每个候选**一把独立种子** | 同上 |
| 街机/电子（2 款） | 转轮结果 | 每个候选一把独立种子 | 只看该游戏资金池的目标返还率 |

**街机不参与偏置和玩家缓刹**——它是一人一局，没有旁人可比。后台界面上那些
「房间偏置」「玩家偏赢/偏输」「玩家缓刹」对街机无效，界面里已经标注了适用范围。

## 三、什么时候会介入

### 3.1 总开关

后台「控奖」页有一个总开关。关掉之后全部游戏走自然随机，没有任何挑选。

### 3.2 彩票与牌桌：三个触发来源

只要命中任意一个就会进入挑选，日志和留痕里会记下是哪个（多个用 `+` 连接）：

| 来源 | 代码里叫 | 什么情况会触发 |
|---|---|---|
| 单期护栏 | `period` | 这一期自然结果会让庄家亏得超过「开档线」 |
| 当日净额 | `dayNet` | 当日整体留存偏离设定的中轴/带宽 |
| 偏置 | `bias` | 管理员对某个房间或某个玩家开了偏置策略 |
| 玩家缓刹 | `brake` | 某个玩家短期赢得过多（超过设定倍数） |

**开档线是按「慢性失血档位」算的，不是后台那个「单期亏损触发线」**：

| 档位 | 开档线 | 什么时候进这档 |
|---|---:|---|
| 正常 | 亏超 50% 才挑 | 默认 |
| 回收 | 亏超 30% 才挑 | 48 小时周期留存亏超 10% |
| 强回收 | 亏超 15% 才挑 | 48 小时周期留存亏超 25% |

退档要回到亏 5% 以内（进出用不同的线，防止来回抖动），且周期流水要够。
档位是**按游戏各自独立**判定的。

### 3.3 有几条「宁可认赔也不动手」的保护

这些是刻意留的，避免做成「老是开你没买的那个」：

- **人少或流水小**：有效人数不足 5 人、或本期流水不足 5000，不允许通杀候选
- **亏得不多**：自然亏损额低于 5000（回收档 3000、强回收 2000），认赔不挑
- **周期已经赚够**：亏损额不超过周期盈利的 20%，认赔不挑
- **候选全都不合法**：回落自然结果，并单独打一条告警日志
  （这是「想控但控不住」，运营最该知道的一种）

### 3.4 街机：只看资金池

街机不看上面那些。它只看该游戏在统计窗口（默认 14 天）内的
累计流水与派彩，挑一个让返还率贴近目标（默认 92%）的候选。窗口之外的盈亏永久落袋。

## 四、怎么介入

### 4.1 候选数量

| 场景 | 候选数 |
|---|---:|
| 彩票/牌桌 · 普通 | 8 |
| 彩票/牌桌 · 强回收 | 16 |
| 彩票/牌桌 · 放水档 | 20 |
| 街机/电子 | 3 |

### 4.2 挑选顺序

多个目标同时存在时按优先级排：玩家缓刹 → 单期护栏 → 当日净额 → 偏置。
候选必须先过「合法性」检查（亏损不超过开档线；通杀候选需要授权），
不合法的直接弃掉。

### 4.3 结算照常

挑完之后，**结算逻辑跟自然开奖完全一样**：一样的赔率表、一样的幂等键、
一样的分批结算、一样的对账。软控不碰钱。

---

## 五、外面能不能查出来

**查不出来。** 这是刻意设计的，也是你当初的要求：软控可以接手结果，
但外部审计不该能证明结果被动过。

具体做了三件事：

| 品类 | 原来的问题 | 现在 |
|---|---|---|
| 牌桌 | 开局前公布承诺 hash，配合 nonce 可反推被改过 | 种子改成**封盘那一刻**才生成，每个候选一把独立种子，只公布被采用的那把；开局前不存在承诺物 |
| 彩票 | 历史接口公开返回 `nonce`，`nonce>1` 等于宣布这期被干预 | 已从对外接口摘掉；种子与指纹照常公布 |
| 街机 | 本来就没有对外公平性宣称 | 不变 |

### 对玩家的说法也跟着改了

验算面板原来写「**可证明公平**」「**承诺** Hash」，这是宣称做不到的事。
现在改成「**开奖可复算**」「**结果指纹** Hash」，并说明玩家实际能验什么：

> 开奖后公布本局种子与其指纹，任何人都能用它复算出同一副牌与同一结果，
> 据此核对公布的结果有没有被改过。

两者差别很实在：
- **结果可复算**（我们提供）：证明公布的结果没被事后改过
- **预承诺公平**（我们不提供）：证明种子不是看完下注才挑的

出纠纷时，宣称做不到的事比从不宣称糟得多，所以措辞必须准。

## 六、内部怎么查

外部查不出来之后，内部必须查得清楚，否则出事时既无法自证清白，
也无法排查是否有人拿软控做手脚。

### 6.1 每次介入都留痕

后台 →「资金对账」旁边的软控留痕（接口 `/console/soft-control-audit`）。
**只有 admin 能看，总监、总代、代理、客服一律 403。**

每条记录包含：

| 字段 | 含义 |
|---|---|
| 品类 / 游戏 / 局号 | 定位到具体哪一局 |
| 触发来源 | period / dayNet / bias / brake / arcadePool，多个用 + 连 |
| 候选数 | 这一局摇了几把 |
| **本来会开什么** | 被放弃的自然结果摘要 |
| **实际开出什么** | 采用的结果摘要 |
| 下注额 / 预估派彩 | 判断这次介入讲不讲得通 |

实际长这样：

```
[table] baccarat BJL20260820-1157   因=dayNet+bias  候选=16
    本来会开: banker
    实际开出: player
    下注 20,000   预估派彩 20,000
```

### 6.2 介入率概览

接口 `/console/soft-control-audit/summary`。分母取同期实际开出的局数，
所以「只在介入时写一行」也能算出比率。

设计上只在**真的放弃了自然结果**时写一行——不介入的局不写。这样行数只跟
介入次数成正比，不会被每一次转轮撑爆，而每一次介入都在。
同一局重复写会撞唯一键，所以结算重放和崩溃续跑都不会重复留痕。

### 6.3 操作日志

管理员对软控做的每次改动（开关、参数、偏置增删启停）都记在操作日志里，
动作分组是「控奖」。**这一组只有 admin 能看**，其他角色连筛选项里都看不到。

### 6.4 对账脚本

`node server/scripts/audit-money.mjs` 的第 8 节会打出各游戏的介入次数与介入率。

## 七、界面 vs 实际（后台上不生效的项）

这些在后台能看到，但**不参与任何判断**。界面里已经置灰并标注，此处再列一遍：

| 项目 | 为什么不生效 |
|---|---|
| 单期亏损触发线 | 真实开档线由慢性失血档位决定（50% / 30% / 15%），此项不参与 |
| 控后冷却 | 冷却会让出防爆权，已停用；运行时恒为未冷却 |
| 庄赢上限 | 已停用 |

后台「控奖」页的设置弹窗里有一块「以下项当前不生效」会逐条说明，
另一块「各项适用范围」会说明哪个开关对哪些品类生效。

## 八、一句话回答几个常见问题

**软控会不会让账算错？**
不会。它只决定开出什么，结算走的是同一套逻辑、同一套幂等键、同一套对账。

**关掉软控会怎样？**
全部游戏走自然随机。账目逻辑完全不变。

**偏置对街机有用吗？**
没用。街机只按资金池目标返还率挑号。

**能不能证明某一局没被动过？**
对外：能证明「公布的结果与公布的种子一致」，不能证明「种子不是挑的」。
对内：admin 查留痕表，介入过的局一定有记录，没记录就是没介入过。

**留痕会不会被删掉看不出来？**
会。这是任何数据库审计的共同局限。如果要做到「删了也能发现」，
需要额外做防篡改链（每条记录带上一条的哈希），目前没做。
