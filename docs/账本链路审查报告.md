# 账本链路审查报告

审查范围：管理上分 → 总代上分 → 代理上分 → 客服 → 玩家上分 → 玩家下注 → 实时开奖 → 报表中心 → 房间详情 → 占成结算。

结论：**资金闭环成立**，本次修掉 5 处越权、1 处可翻倍入账、3 处口径不一致、6 处命名冲突。测试 58 套件 427 条全过，前后端构建通过。

---

## 一、这个系统是怎么运行的

### 1. 钱怎么下来（发额度）

```
平台池 ──► 总代 ──► 代理 ──► 客服 ──► 玩家
      ◄──      ◄──      ◄──      ◄──   （回收 / 下分）
```

每一层「上分」都是**双边记账**：出方一条 OUT、入方一条 IN，同一事务写入。

三本账各管一段，缺一不可：

| 账本 | 管什么 | 唯一写入口 |
|---|---|---|
| `PointsLedger` + `PointsAccount.balance` | 余额真账 | `PointsService` |
| `AgentQuotaLedger` + `Agent.pointsQuota` | 盘分额度真账 | `writeAgentQuotaInTx` |
| `CreditIssueDebt` | 信用盘「先用后付」的欠条 | `recordCreditIssueDebtInTx` |

**为什么闭环成立**：`pointsQuota` 全仓库只有一处 `agent.update`，`balance` 只有 `PointsService` 能改，没有任何绕路。`fund-recon` 每天 05:00 自动核：逐账户「余额 = 流水之和」、逐代理「额度 = 额度流水之和」、全站余额 = 全站流水净额、冻结额 = 待审下分单、信用盘守恒。**核不平就锁死出款闸门**，玩家提不了现。

### 2. 钱怎么动（下注）

下注时把「谁坐庄」快照进注单 `payload.fly`，之后所有统计都认这个快照，不再回头推算：

| 组合 | 含义 |
|---|---|
| `flying=true, sitting=PLATFORM` | 飞上台，平台坐庄 |
| `flying=false, sitting=GENERAL` | 总代坐庄（总代关盘，或代理额度不够飞到总代） |
| `flying=false, sitting=AGENT` | 代理自己坐庄（关盘） |

下注必须带 6 位房号且人在房内，否则直接拒绝——所以每笔注都带房间号。

### 3. 钱怎么结（三张单）

| 单据 | 谁跟谁 | 只收哪一截 |
|---|---|---|
| 总代总表 | 平台 ↔ 总代 | 只收**飞上台** |
| 房间结算单 | 总代 ↔ 代理（直挂房则平台↔代理） | 收**代理飞出去的**（上台 + 飞到总代） |
| 关盘 | 谁坐庄谁自负 | **不进任何单** |

账期按设定时间自动切（周结＝上海周一 00:00，月结 1 号，半月结 15/30）。

**结账按开奖时间归期**——输赢在开奖那一刻才定，派完彩这一期才算完。跨点那笔（23:58 下注、00:03 开奖）落到它开奖的那一期，两期不重不漏，所以不需要拦着不让结账。经营看板另一套：按下注时间且含未开奖，回答「今天打了多少」。

结钱是人工点的，自动的只有信用盘每小时 :07 的封账快照。

## 二、本次修掉的问题

### A. 越权（5 处，都已修）

| 问题 | 后果 | 修法 |
|---|---|---|
| 总代总表未校验总监授权 | 总监换个 id 就能看任意总代的合同（占成、费率、信用额度）和**历次结账全部金额**——history 直接按 id 查快照表，没有任何房间过滤兜底 | `resolveTarget` 加 `generalVisibleToBranch` |
| 应付账龄查全站 | 总监能看到未授权房间的房号、结账金额、欠付天数 | 接口传 actor，按授权房间收窄；定时巡检仍查全站 |
| `GET console/logs` 隔离过弱 | 非超管只按「操作人是自己」过滤，比 `/admin/logs` 弱一截；前端根本没用 | 删除该接口 |
| 玩家流水榜按代理树取人 | 挂在树下但不在自己房的玩家也上榜；客服能看到派单以外的人 | 改走 `playerWhere`，与玩家列表同一把尺 |
| 上下分单放行总监 | 按代理树前缀过滤，对总监既筛不准又可能漏出未授权房的单 | 收掉总监权限，其余角色加兜底 |

### B. 资金风险（1 处，已修）

**同一订单号可двойн入账。** 控制台直接上分用 `console_credit:{订单号}`，充值审核用 `recharge_approve_{内部id}`，两个幂等键在不同命名空间，互相拦不住。先在控制台上一笔、再去审核页点通过，玩家会被入账两次。

修法：上下分前先查 `RechargeOrder.orderNo`（唯一键），有同号申请单就拒绝，提示去审核页处理。

### C. 口径不一致（3 处，已修）

| 问题 | 后果 | 修法 |
|---|---|---|
| 注单明细对缺房号的单用「玩家当前所在房」兜底，聚合只认注单房号 | 同一间房「明细」比「流水」多一截，永远差一点；玩家换房还会改动历史报表 | 明细改为只认注单房号 |
| 注单明细不过滤已取消 | 明细里有、汇总里没有 | 明细排除 CANCELLED |
| 三方拆账逻辑在三处各写一遍 | 改一处漏两处 | 收进 `flow-scope.helper.ts`，页面与单测共用 |

### D. 命名冲突（6 处，已修）

定死两条规则：**余额 = 手上的盘分；额度 = 合同 / 剩余信用。** 两个词不许混用。

| 位置 | 改前 | 改后 |
|---|---|---|
| 顶栏（总代） | 可用额度（实际是余额） | 总代余额 |
| 客服账号页 | 我的余额 | 代理余额（与顶栏同名） |
| 账号中心代理列 | 余额 / 上盘·剩余信用 | 代理余额 / 剩余信用·可用额度 |
| 账号中心总代行 | 额度 xxx | 合同额度 xxx |
| 总代结算房间表 | 成数差 | 总代占成（与同页 hero 同名） |
| 总代结算历史 | 总代占成（实为总代+代理合计） | 总代侧占成合计 |
| 总代详情房间表 | 平台占成（总代自己看也叫这个） | 总代看到「我的成数差」 |
| 代理工作台本周占成 | 平台占成 / 代理占成 / 本周流水 | 应上缴上家 / 我的占成 / 本周结账流水 |

## 三、每个角色看什么

### 管理（ADMIN）

**能进**：工作台、房间中心、账号中心、结算中心、资金对账、报表中心、实时开奖、游戏管理、控奖中心、回水规则、风控告警、操作日志。全站无隔离。

**看到的钱**：只看**飞上台**。关盘由总代/代理自负，不进平台账，管理侧一律不显示。

| 位置 | 显示项 |
|---|---|
| 工作台 | 飞盘流水、庄家盈亏、给代理上分、收回代理 |
| 房间中心 | 飞盘流水、庄家盈亏（无飞/关拆分） |
| 报表中心 | 上块「本期结账口径」：结账投注额 / 结账庄家盈亏 / 平台占成；下块经营 |
| 实时开奖 | 本期飞盘、今日飞盘 |
| 结算中心 | 总代总表：结账投注额、总代侧占成合计、平台占成、本期交割 |

**看不到**：无。顶栏不显示个人钱包（管理没有盘分）。

### 总监（BRANCH）

与管理相同的口径（只看飞上台），但**范围限于授权房间**：挂总代的房需该总代被授权，直挂房需该房被授权。

**看不到**：未授权总代的合同与结账历史、未授权房间的账龄、未授权房间的任何经营数据。名下有未授权房时**不能代结**该总代的总表。

**不开放**：资金对账、游戏管理、控奖中心、上下分单。

### 总代（GENERAL，含挂在总代下的子账号）

**能进**：工作台、房间中心、账号中心、结算中心、报表中心、实时开奖、回水规则、操作日志。范围＝名下全部房间。

**看到的钱**：飞 + 关都算。

| 位置 | 显示项 |
|---|---|
| 顶栏 | 总代余额、房间余额、上盘可飞 |
| 工作台 | 今日流水 / 飞上台 / 关盘、庄家盈亏 |
| 房间中心 | 今日流水（下标：上台 X · 关 Y）、关盘汇总 |
| 总代详情 | 剩余信用（信用盘）或可用额度（现金盘）、合同额度、今日流水 / 飞上台 / 关盘、我的成数差 |
| 报表中心 | 结账口径块显示「我的成数差」；经营块拆飞上台 / 关盘 |
| 结算中心 | 自己那张总表；跟代理按房拆 |

**看不到**：别的总代的任何数据（接口强制落到自己），平台内部那份占成（显示为「我的成数差」）。

### 代理（AGENT，含挂在代理下的子账号 PROXY）

**能进**：工作台、我的房间、客服上下分、客服账号、报表中心、实时开奖、回水规则、操作日志。范围＝自己绑定的房间。

**看到的钱**：飞 + 关都算，「飞」含飞到总代那截。

| 位置 | 显示项 |
|---|---|
| 顶栏 | 代理余额、客服额度、上盘可飞、玩家持分 |
| 工作台 | 今日流水 / 飞盘 / 关盘、本房盈亏、上分 / 下分（信用盘：今日发分、预估占成）、本周结账流水 / 我的占成 / 应上缴上家 |
| 我的房间 | 今日流水（下标：飞 X · 关 Y） |
| 房间详情 | 代理余额、客服额度、上盘可飞、玩家持分；信用盘另有合同额度、超出 |
| 报表中心 | 结账口径块：结账投注额（自己飞出去的）、结账庄家盈亏；经营块拆飞盘 / 关盘 |
| 房间结算单 | 结账投注额、派彩、庄家盈亏、上下分、月费、佣金、占成、本期交割 |

**看不到**：结算中心（平台↔总代总表）、别的代理的房间与玩家、风控、资金对账、游戏与控奖。

### 客服（CS）

**能进**：只有客服上下分页（登录直接跳转）。

**看到的钱**：顶栏「客服额度」＝自己账上的余额；只能看到**系统派给自己**的玩家的订单与详情。

**看不到**：全部玩家列表、房间数据、报表、结算、任何经营 KPI。

### 玩家（client-app）

只看自己的积分与流水，与后台「玩家持分」是同一字段。

## 五、故意不对平的地方（不是 bug）

对账时最容易吵架的四条，先记住：

1. **经营 ≠ 结账**。经营按下注时间、含未开奖与关盘；结账按开奖时间、只算飞盘。
2. **总表 ≠ 房间单**。总表只收飞上台，房间单收代理飞出去的。总代坐庄那截只在房间单里。
3. **流水 ≠ 有效流水**。报表「流水」取下注额；回水、佣金取 `validFlow`。和局退本时后者为 0。
4. **报表 ≠ 资金对账**。对账查的是账本有没有坏，不是经营统计对不对，两者不该逐行相等。

## 七、上线前自测

数据库起来后先跑一次，确认没有历史脏单：

```sql
SELECT count(*) FILTER (WHERE NULLIF(payload->'fly'->>'roomId','') IS NULL) AS 无房号,
       count(*) AS 总数
FROM "Bet";
```

然后同一间房下三笔注（飞盘全开 A、总代整房关盘 B、代理整房关盘 C），等开奖后核对：

- 管理只看得到 A
- 总代合计 = A + B + C，飞上台 = A，关盘 = B + C
- 代理合计 = A + B + C，飞盘 = A + B，关盘 = C
- 房间结算单结账投注额 = A + B
- 总代总表结账投注额 = A
- 报表「本期结账口径」块与上面两张单一致
- 开奖前就点结清：能点，账单里不含还没开的那几笔；等它们开完，下一期收得到
